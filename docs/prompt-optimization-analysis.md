## 核心问题：能否"少代码 + 多描述"达到同样效果？

**简短回答：理论上可以，但对当前使用的 4B 小模型（Qwen3-4B-Instruct）来说，效果会明显下降。**

### 原因一：代码模板的真正作用不是"教模型写代码"，而是"约束输出格式"

这些模板本质上在做三件事：

1. **锚定文件路径格式**：`CSV_PATH = r"..."` + `OUTPUT_DIR = Path("generated")` → 防止模型自己发明路径写法
2. **锚定输出文件名**：`enrolled_summary.csv`、`enrolled_school_dist.png` → 防止模型随意命名导致验证失败
3. **锚定代码结构**：读数据 → 处理 → 写 CSV → 画图 → 保存 PNG → close → print → 确保完整流程

### 原因二：模型规模决定了"描述→代码"的转化能力

| 模型规模 | 描述性指令理解力 | 需要的代码模板量 |
|----------|----------------|----------------|
| 70B+ (GPT-4, Qwen2.5-72B) | 强 | 1 个通用模板即可，其余用描述 |
| 14B-32B | 中 | 需要 2-3 个关键模板 + 描述 |
| **4B（当前使用）** | **弱** | **需要逐轮具体模板才可靠** |

Qwen3-4B 的具体问题：

- 对复杂约束的**遵循一致性差**（比如"第 2-6 轮用 CSV，第 7 轮才用 SQLite"，用纯描述很容易在第 4 轮就跑去连数据库）
- 对隐含意图的**推理能力弱**（比如描述"统计学校分布"，4B 可能不会主动想到 `value_counts() → barplot`）
- **上下文窗口利用率低**——看到代码模板能直接模仿，但看到长段文字描述，提取关键信息的能力不稳定

### 原因三：第 8、9 轮的完整脚本是特殊情况

第 8 轮（README 生成）和第 9 轮（综合报告）的脚本之所以写得这么完整，是因为：

- README 有**严格的格式验证**（`validate_readme_document`），格式偏差会导致反复重试
- 综合报告需要**读取前面轮次的 CSV 文件做交叉分析**，逻辑较复杂
- 4B 模型很难仅凭描述生成满足所有格式要求的代码

## 可行的精简方案

### 方案 A：保守精简（适合 4B 模型）

**目标**：816 行 → 约 500 行

| 可以精简的 | 做法 | 预计节省 |
|-----------|------|---------|
| 第 2、3 轮的完整示例 | 合并为 **1 个通用 CSV 分析模板**，附带变量占位 | ~60 行 |
| 代码模板 A/B/C | 删除 A 和 C，只保留 B（SQLite） | ~60 行 |
| 第 4-6 轮的防错规则 | 精简为表格（字段名 → 注意事项） | ~40 行 |
| 第 9 轮模板 | 保留 **骨架**（前 30 行），删除交叉分析的具体实现 | ~100 行 |

**保留不动的**：

- 第 8 轮 README 脚本（格式验证太严格，必须给完整模板）
- 第 7 轮 SQL 示例（多表 JOIN 对 4B 必须示范）
- 所有"禁止/强制"类约束规则

### 方案 B：激进精简（需换更大模型，14B+）

**目标**：816 行 → 约 200 行

- 只保留 **1 个 CSV 模板 + 1 个 SQL 模板**
- 所有轮次要求压缩为一张表：`| 轮次 | 数据源 | 输出 CSV | 输出 PNG |`
- 第 8、9 轮只给格式要求，不给代码
- 防错规则只保留 Top 5 最关键的

---

## 精简的收益与风险

### 收益

- **减少 token 消耗** → 每轮请求的 prompt tokens 更少 → 生成速度略微提升
- **减少注意力分散** → 更紧凑的规则反而可能提高遵循率

### 风险

- 4B 模型在没有代码模板的情况下，**文件命名、路径格式、代码结构**的一致性会下降
- README 和综合报告的格式可能无法通过验证，导致更多重试轮次

---

## 建议

> **当前阶段（4B 模型）：执行方案 A 的保守精简，同时保持核心模板不变。**

**不能省掉的关键内容**：

1. 逐轮的输出文件名定义（后端验证依赖这个）
2. 至少 1 个完整的 CSV 模板和 1 个 SQL 模板
3. 第 8 轮的 README 完整脚本

**未来升级路径**：

- 切换到 14B+ 模型后，可进一步执行方案 B
- 最终目标：提示词以"任务描述 + 约束规则 + 输出规范"为主，代码模板降到最低限度
